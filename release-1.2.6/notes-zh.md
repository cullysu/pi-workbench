# v1.2.6 — 两个 P1 阻断与供应链物理钉住

第十六轮独立评审（v1.2.5 全版本审查，30 组问题）的两个 P1 阻断与经核实的 P2 项全量落地。这轮最重要的成果是一条**供应链铁证与修正**。

### P1 ×2（主要通道阻断）
- **macOS 构建现在会生成外壳完整性清单**：afterPack 钩子此前只认 Windows/Linux 的 `resources/app` 布局，mac 的 `.app/Contents/Resources/app` 静默漏写——而打包版启动又强制要求该文件（等于 mac 包必拒启）。两种布局都处理，找不到时大声失败。
- **MCP 一键安装现在装出 pi 真正能发现的东西**：pi 只通过 `index.js` 入口发现子目录扩展（loader.js resolveExtensionEntries），此前安装成 `mcp-bridge.js`——接口返回成功而引擎发现列表为空。现按入口契约安装为 `index.js`；typebox 随运行时捆绑，干净机器首装**不再依赖系统 npm**。

### 供应链铁证：发布包里的依赖与锁文件不一致
- CI 的 SBOM 直接读取物理安装树，证实 **v1.2.4/v1.2.5 发布包内的 undici 实为 8.9.0**（brace-expansion 5.0.9 同理），尽管锁文件写着 8.11.2/5.0.12——npm 的 overrides 与锁文件编辑在这棵树上都被安装器忽略。
- 修正：新增打包期 pin 步骤**物理覆写**传递依赖副本（write-manifest 之前，清单哈希的是钉住后的树），SBOM 步骤对钉住版本做**硬断言**——审计门禁与发布字节从此不可能再各说各话。

### 状态一致性与正确性（核实后修复的 P2/P3）
- **cron**：第一次 tick 里的第二次 boot-reset（可能双重启动手动任务）移除；设置保存不再复活超过僵尸超时的死 running 标志；无人值守任务现在沿用面板的技能开关与默认模型。
- **密钥轮换**：成功上报携带 `tabId`，clearCool 收窄到真正服务过的 key——健康 key B 的成功不再解冻坏 key A。
- **POSIX 退出清理**：server 与 pi 分属不同进程组，垂死的 server 现在主动收割自己的 pi 组（含其 MCP/工具子进程）。
- **前端状态组**：目标自动续跑定时器在触发时重查停止状态与 tab 归属；pi 退出即释放死 tabId（不再静默吞发送）；回放登记工具卡片（工具结果有处可落）；会话导出去掉不可能满足的前置条件；会话树从窗口裁剪后的根渲染（>4000 节点不再整页空白）。
- **数据正确性**：分模型估算费用向上折入总计（此前恒 0）；日统计带 cacheWrite；ZCode 账本保留 cacheWriteTokens 且不再把模型对象打成 `[object Object]`；Codex 窗口外记录不再塞进查询窗口。
- **其它**：供应商"真实回信"测试把空 HTTP 200 判为失败；MCP 工具失败带 `[MCP error]` 标记、`tools/list` 跟随分页、懒加载元工具描述各工具参数；备份导入做结构校验（语法合法的垃圾不再覆盖有效配置）；`readJsonl` 对无换行巨行立即丢弃；配置写入 rename **前** chmod 0600（消除 0644 窗口）；项目标识仅在 Windows 折叠大小写（POSIX 的 `Foo/` 与 `foo/` 不再被合并）；Electron 端口探测发送带端口 Host（此前把自己服务器误判为端口占用者）；全新安装能创建日志文件；runtime manifest 覆盖 `node_modules` 且双壳拒绝空清单；Tauri 的 `target=_blank` 交系统浏览器（修复更新下载链接无动作）。
